# 视觉规格：戴夫突围

## 文档职责

本文档描述《戴夫突围》的运行时视觉表现，包括画面风格、方向动画、HUD、升级弹窗、结算面板、VFX、地图视觉边界、正式截图限制和视觉证据要求。

本文档不定义玩法数值、伤害公式、升级效果、波次节奏或胜负规则；这些内容以 `spec/游戏机制.md` 为准。本文档不定义素材目录边界；素材接入以 `assets/README.md` 及其子文档为准。本文档不定义详细测试步骤；测试步骤由 `test-author` 根据验收标准输出到 `docs/` 目录。

## 总体视觉目标

游戏整体是手绘描边、暗色高对比的漫画街机风，不做像素化处理。正式运行画面应让不看文档的验收者在短时间内看懂：戴夫在地图里移动，自动放豌豆攻击一波波僵尸。

运行时视觉必须优先使用正式美术、动画、运行时 UI 资产、粒子、短暂反馈和音画结合来表达状态。正常游玩入口和正式视觉验收截图不显示开发调试标记。

## 分辨率、镜头和地图视觉

- 设计分辨率为 1920x1080。
- 素材按原始像素 1:1 显示，Camera2D zoom 默认保持 1；如实际观感需要，可在 0.8 到 1.2 之间微调。
- 主地图 `full_outdoor_map_painted_4096x2305.png` 一屏约看到整图四分之一，不能一次性显示整张地图。
- 地图边界必须通过围栏、树墙、石墙、水面、暗草边、碎石带或地形变化表达。正常画面不能用矩形描边、透明色块、坐标框或开发者边界线表达可走范围。
- 环境装饰由 Godot 在底图上叠加：围栏、树墙、石墙沿 `full_outdoor_map_manifest.json` 的视觉边界布置，水面 2 到 3 处，草丛、石头、土堆在开阔区零散分布。刷怪区和玩家出生点附近保持空旷可读。

## 方向动画

角色、豌豆弹、毒液和僵尸的运行时方向表现必须跟随当前移动或飞行方向。

方向分为 8 向：

- 东：`e`
- 东南：`se`
- 南：`s`
- 西南：`sw`
- 西：`w`
- 西北：`nw`
- 北：`n`
- 东北：`ne`

运行时动画规则：

- 戴夫移动时使用 `walk_<方向>`；停止移动时保持最后朝向，并使用 `idle_<方向>`。
- 普通僵尸、铁桶大僵尸、吐毒液远程僵尸移动时使用 `walk_<方向>`。
- 橄榄球小僵尸移动时使用 `run_<方向>`。
- 橘豌豆、熔岩豌豆和毒液按当前飞行方向使用 `fly_<方向>`。
- 西瓜豌豆按当前飞行方向使用 `spin_<方向>`。

不能只加载 8 向图集却固定播放单一方向动画。正常战斗画面里，戴夫、豌豆、毒液和僵尸的朝向不能和运动方向明显相反或错乱。

## HUD 布局

HUD 使用 CanvasLayer 或等价方式固定在屏幕上，镜头移动时比例和位置不随地图漂移。

左上 HUD 组包含头像、血条、经验条和已解锁豌豆图标：

- 头像位于左上区域。
- 血条位于头像右侧。
- 经验条位于血条正下方。
- 血条和经验条的槽体左边缘、右边缘、内容内边距必须视觉对齐。
- 血条填充和经验条填充必须位于各自槽体内部，不能偏出边框、悬空、错位或出现孤立色块。
- 已解锁豌豆图标位于经验条下方或左下方，不能遮挡或打断血条、经验条的对齐关系。

血条和经验条的对齐按 1920x1080 基准视口判定。这里不要求整个 HUD 逐像素复刻示意图，但血条和经验条之间的几何关系必须可测量：

- 血条槽体矩形：血条可见外框或底槽的外接矩形。
- 经验条槽体矩形：经验条可见外框或底槽的外接矩形。
- 血条内容区矩形：血条槽体内部实际允许血量填充出现的区域。
- 经验条内容区矩形：经验条槽体内部实际允许经验填充出现的区域。
- 血条填充矩形：当前血量填充的可见区域。
- 经验条填充矩形：当前经验填充的可见区域。

具体对齐要求：

- 血条槽体矩形左边缘 x 坐标与经验条槽体矩形左边缘 x 坐标，差值不超过 2 px。
- 血条槽体矩形右边缘 x 坐标与经验条槽体矩形右边缘 x 坐标，差值不超过 2 px。
- 血条内容区矩形左边缘 x 坐标与经验条内容区矩形左边缘 x 坐标，差值不超过 2 px。
- 血条内容区矩形右边缘 x 坐标与经验条内容区矩形右边缘 x 坐标，差值不超过 2 px。
- 血条填充矩形必须完整落在血条内容区矩形内。
- 经验条填充矩形必须完整落在经验条内容区矩形内。
- 血条填充矩形左边缘应贴合血条内容区矩形左边缘，差值不超过 2 px。
- 经验条填充矩形左边缘应贴合经验条内容区矩形左边缘，差值不超过 2 px。
- 经验条必须位于血条正下方，不能横向漂移到头像下方、槽体外侧或独立成为一块色块。
- 如果 HUD 运行时存在整体缩放，上述容差按缩放比例同步放大；未缩放或缩小显示时，最低容差仍按 2 px 计算。

顶部居中区域显示波次和新豌豆提示。右上区域显示击杀数和计时。`spec/v0.1-画面基准-战斗HUD示意.png` 是 v0.1 HUD 的视觉基准，用于约束信息位置、比例、层级和对齐关系。

## 升级弹窗

`spec/v0.1-画面基准-升级弹窗示意.png` 是 v0.1 升级弹窗的视觉目标，不只是普通参考图。最终实现不能直接切取或贴用示意图，但必须按示意图重绘或生成运行时 UI 资产，并保留它的核心结构、比例和视觉重心。

升级弹窗视觉绑定项：

- 升级三选一弹窗必须居中出现，弹出时压暗战场，但战斗背景仍然可见。
- 三个升级选项必须是三张并排的竖向大卡片，不得改成长条按钮列表、普通菜单列表或默认系统面板。
- 三张卡片的整体尺寸、间距、视觉重心和占屏比例应接近 `spec/v0.1-画面基准-升级弹窗示意.png`。
- 每张卡片必须保留明显的外框、内框、上半部主内容区、下半部说明区和底部圆形徽章或图标位。
- 卡片可以根据实际升级内容加入名称、效果、当前层数和倍率文案，但文案排布不能破坏竖向卡片结构。
- 选中、悬停或可点击反馈可以用描边、亮边、发光、颜色变化或轻微缩放表达，但不能把卡片改成其他布局。
- 允许重新绘制纹理、边框、图标和文字样式；不允许直接切取示意图作为最终 UI 资源。
- 升级卡外框、内框、底纹、底部徽章和主要图标必须来自 `assets/sprites/ui/runtime/` 的运行时 UI 资产，或来自这些资产建出的 `.tres`。
- 如果实现仍主要依赖 `draw_rect`、`draw_line`、`draw_circle`、默认 `Button`、默认 `Panel` 或单色 `StyleBoxFlat` 来模拟卡片外观，即使结构位置接近，也不算达到 v0.1 升级弹窗视觉目标。
- 升级卡必须至少对照 `assets/sprites/ui/reference_crops/upgrade_card_normal_ref.png`、`upgrade_card_gold_ref.png` 和对应升级图标 crop 生成运行时资产，并保留参考 crop、运行截图 crop 和并排对照证据。

## 结算与暂停面板

胜利和失败结算面板居中弹出，展示本局结果、存活时间、击败敌人数、放出豌豆总数、最常用豌豆或最高伤害豌豆、升级次数。按钮和统计文字不能互相遮挡。

暂停面板应明确表示当前暂停状态，并提供可恢复操作。暂停画面不能遮挡到无法辨认当前战场和 HUD 状态。

## 豌豆的视觉表现

豌豆作为一次性子弹发射出去。豌豆的差异必须通过整豌豆造型、飞行动画、弹道、残影、命中粒子和短暂特效表达。正常画面不能用常驻命中半径圈、爆炸预告圈或范围辅助线替代豌豆的正式表现。

| 豌豆 | 正式视觉识别方式 | 不允许的替代方式 |
| --- | --- | --- |
| 橘豌豆 | 橘色整豌豆扑击、直线飞行、短直线残影、命中小火花 | 常驻命中半径圈、目标锁定框 |
| 熔岩豌豆 | 熔岩豌豆扑击、落点短暂爆炸、烟尘或橙色冲击波 | 常驻爆炸半径预告圈、从发射到命中一直显示的大范围圆 |
| 西瓜豌豆 | 外表就是一个西瓜、弧线或回旋轨迹、扫场残影、短暂命中波纹 | 常驻大范围圆环、几何扫场半径线 |

## 僵尸的视觉表现

四种僵尸必须靠正式美术和行为差异被玩家识别。正常画面不能用头顶常驻文字、类型徽标、碰撞圈、AI 范围圈或矩形状态框来替代敌人造型。

| 敌人 | 正式视觉识别方式 | 不允许的替代方式 |
| --- | --- | --- |
| 普通僵尸 | 标准体型、普通移动动画、黑白花纹、数量压力 | 头顶常驻“普”标签、脚下碰撞半径圈 |
| 橄榄球小僵尸 | 更小体型、更快跑动动画、明显前倾、短暂速度残影 | 头顶常驻“快”标签、常驻速度线或检测线 |
| 铁桶大僵尸 | 更大体型、更厚轮廓、更慢步伐、更沉的受击反馈 | 头顶常驻“厚”标签、红色矩形框、护甲检测框 |
| 吐毒液远程僵尸 | 不同角或嘴部造型、吐毒液动作、毒液弹体、保持距离行为 | 头顶常驻“远”标签、蓝色 AI 范围圈 |

## VFX 与反馈

UI 控件、命中、爆炸、经验、死亡、戴夫受击等反馈使用按运行尺寸准备的定制资产或粒子效果。不能直接切原始参考大图凑成最终效果，也不能只用纯色框或默认控件代替。

必须能看出：

- 敌人被打到时有闪白、闪烁、粒子或其他可见受击反馈。
- 豌豆命中有反馈。
- 熔岩豌豆爆炸有范围特效。
- 西瓜豌豆扫场能看出命中过程。
- 戴夫受击时有可见反馈，并能从 HUD 血量变化看出扣血。
- 战斗中可以有轻微震屏、视觉抖动或短暂停顿，但不能影响玩家读 UI 和走位。

## 调试辅助层限制

正常游玩入口必须呈现玩家视角的正式画面，不显示调试辅助层。正式视觉验收截图中不得出现：

- 碰撞半径圈
- 攻击半径圈
- 激活范围圈
- 刷怪区矩形
- 地图边界矩形
- 敌人类型文字标签
- AI 状态标签
- 对象池标记
- 坐标标记
- 开发者辅助线

需要这些信息时，必须通过显式调试入口单独截图，并在文件名或报告里标明调试辅助层已开启。

## 视觉证据

UI、布局、动态特效和结算页必须有真实运行截图或帧序列证据，不能只靠日志、控件坐标或 headless 结果判定通过。

每轮正式视觉验收至少保留：

- 正常战斗 HUD 截图。
- 升级弹窗截图。
- 胜利或失败结算截图。
- 能看到战斗动态、方向动画、命中或受击反馈的连续帧或短录屏。
- 必要时保留参考图、运行截图 crop 和并排对照证据。
