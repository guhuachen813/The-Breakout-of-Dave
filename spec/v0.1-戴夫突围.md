# v0.1 一局制可用版：戴夫突围

v0.1 的目标：在仓库根目录完成一个 Godot 4.x 项目（含 `project.godot`），交付《戴夫突围》的一局制核心闭环：可打开、可游玩、可结算、可重开、可验证。桌面运行优先，保留 Web 导出可能。

## 事实源分工

本文档只定义 v0.1 交付范围和文档入口，不重复维护机制、视觉和素材细则。若本文档与事实源冲突，以对应事实源为准。

## 必须交付的闭环

按 `spec/游戏机制.md` 完整实现一局制核心闭环：

1. 进入固定大地图。
2. 戴夫可以移动，镜头跟随。
3. 戴夫自动放豌豆攻击敌人。
4. 敌人按波次出现并形成压力。
5. 敌人死亡后掉经验，经验吸附到戴夫并推进升级。
6. 升级时出现三选一，玩家选择后回到战斗。
7. 指定波次结束时固定解锁新豌豆。
8. 戴夫血量归零进入失败结算。
9. 撑过最后一波进入胜利结算。
10. 结算页能重开新一局。

## 必须满足的视觉入口

按 `spec/视觉规格.md` 完整实现 v0.1 所需视觉表现：

- 正常游玩入口呈现正式画面，不混入调试辅助层。
- 角色、豌豆弹、毒液和僵尸按当前方向使用对应方向动画。
- HUD、升级弹窗、结算面板、VFX 和正式截图限制符合视觉规格。
- `spec/v0.1-画面基准-战斗HUD示意.png` 约束战斗 HUD 的信息位置、比例、层级和对齐关系。
- `spec/v0.1-画面基准-升级弹窗示意.png` 约束升级弹窗的结构、比例和视觉重心。

## 素材边界

- 运行时素材只用 `assets/sprites/`（含 `.spriteframes.tres`）和 `assets/audio/sfx/` 中允许接入的资源。
- `assets/source/` 是源图目录，不接入运行时。
- `ui_assets_painted.png`、`combat_assets_painted.png` 等 painted 图只作风格参考；最终运行时 UI 和 VFX 使用按实际尺寸准备的运行时资产。
- `assets/sprites/ui/reference_crops/` 是控件级视觉参考；`assets/sprites/ui/runtime/` 是 Godot 实现应引用的运行时 UI 资产目录。
- Godot 代码不引用 `.import` 文件；`.import` 只作为 Godot 导入元数据存在。
- 音效是必交项：接入 `assets/audio/sfx/` 的真实音频，战斗、UI、升级、波次、胜负等关键事件触发对应 SFX。
- 不移动、不改名现有素材目录。

## 代码结构

输入、战斗、刷怪、升级、结算、音效、观测入口分模块实现。公共数值集中管理，不把规则和数值写死在 UI、动画或特效脚本里。

## 可调试与可验证

- 主场景可直接运行，控制台无脚本报错和资源加载错误。
- 关键状态可观测：玩家血量、当前波次、敌人数量、豌豆弹数量、毒液数量、击杀数、经验、升级次数、已解锁武器和游戏状态。
- 支持固定随机种子。
- 提供能快速验证升级、胜利、失败和关键战斗状态的调试入口。
- 允许提供调试辅助层，但必须默认关闭，只能通过明确参数或验证入口开启；调试截图和报告必须标明调试辅助层已开启。
- UI、布局和动态特效必须用真实运行截图或动态帧序列验证，不能只靠 headless smoke、控件 rect 或日志指标判断。
- 页面和 UI 上不写“已完成某某需求”之类说明文字，完成与否靠游戏本身和验证证据体现。

## 非目标

v0.1 不做复杂主菜单、剧情对话教程、商店背包天赋、存档、账号、排行榜、多人联机、后端服务、多关卡、随机地图、复杂 Boss、新增豌豆种、新增敌人技能、移动端适配、发布打包优化、更换引擎或语言。
