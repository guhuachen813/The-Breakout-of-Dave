# 戴夫突围 v0.1 验收标准

## 文档职责

本文档用于判定《戴夫突围》v0.1 是否达到“可打开、可游玩、可结算、可重开、可验证”的合格线。

- 本文档对应 `AGENTS.md` 开发流程里的 step 1，由主 Agent 根据 spec 整理或确认。
- 本文档只写“什么算通过”，不展开详细测试步骤。
- 详细测试用例和运行方法应由 `test-author` 根据本文档输出到 `docs/` 目录。
- 覆盖检查应由 `acceptance-checker` 核对：每条验收标准都要有真实测试或人工检查证据。
- 玩法事实源是 `spec/游戏机制.md`；视觉事实源是 `spec/视觉规格.md`；v0.1 范围和素材边界参考 `spec/v0.1-戴夫突围.md`、`assets/README.md` 及其子文档。
- 如果本文档和事实源冲突，以对应事实源为准，并先修正本文档再继续开发或验收。

## 总通过口径

v0.1 通过验收，需要同时满足下面几件事：

- 游戏能作为 Godot 4.x 工程直接运行。
- 一局能从开始进入战斗、升级、波次推进、胜利或失败结算，并能重开。
- 核心玩法、UI、音效、反馈、性能和观测证据都达到本文档的标准。
- 每条验收标准都有对应测试、截图、帧序列、日志、状态快照或人工复核记录。
- 不为了让实现过关而降低验收标准、测试要求或事实源口径。

## 一、项目可运行与范围

- **AC-RUN-01** 仓库根目录是 Godot 4.x 工程，包含 `project.godot`，主场景为 `scenes/Main.tscn`，主场景能直接启动。
- **AC-RUN-02** 主场景启动和正常游玩时，没有脚本解析错误、资源加载错误或运行时致命错误。
- **AC-RUN-03** 运行时素材只引用 `assets/sprites/` 和 `assets/audio/sfx/` 中允许接入的资源，不把 `assets/source/` 当作运行时资源。
- **AC-RUN-04** 输入、战斗、刷怪、升级、结算、音效和调试观测入口分模块实现，不能把主要规则混写进 UI、动画或一次性调试脚本里。
- **AC-RUN-05** 波次、升级、豌豆、敌人、音效事件、数量上限等公共数值集中管理，有唯一口径，不能散落硬编码在多个脚本里。
- **AC-RUN-06** v0.1 不引入非目标内容：存档、账号、排行榜、商店、背包、天赋树、第二张地图、随机地图、多人、后端、复杂 Boss、新增豌豆种、新增敌人技能、移动端适配或发布打包优化。

## 二、可观测与证据

- **AC-OBS-01** 游戏支持固定随机种子；同一个种子、同一组输入和同一套调试参数下，关键状态推进可复现。
- **AC-OBS-02** 任意关键时刻能导出状态快照，至少包含：戴夫血量、最大血量、当前波次、波次进度、游戏时间、游戏状态、场上敌人数、场上豌豆弹数、场上毒液数、击杀数、当前经验、升级所需经验、升级次数、已解锁武器、各升级层数。
- **AC-OBS-03** 提供快速进入升级、胜利、失败三个流程的调试入口，不要求验收者每次都完整打满一局才能检查这些状态。
- **AC-OBS-04** UI、布局、动态特效和结算页必须有真实运行截图或帧序列证据，不能只靠日志、控件坐标或 headless 结果判定通过。
- **AC-OBS-05** 每轮正式验收至少保留战斗、升级弹窗、胜利或失败结算三类截图，以及一段能看到战斗动态的连续帧或短录屏。

## 三、输入、暂停与交互

- **AC-INPUT-01** 玩家能用 WASD 和方向键移动戴夫；上下左右和斜向移动都稳定，斜向移动不能明显快于单轴移动。
- **AC-INPUT-02** 戴夫移动时镜头跟随，玩家不能走出地图视觉边界或进入不可读的地图外区域。
- **AC-INPUT-03** 玩家不需要手动瞄准或主动攻击；豌豆会从戴夫附近自动发射并攻击敌人。
- **AC-INPUT-04** 升级三选一出现后，玩家能用鼠标点击任意可选升级项；选中后升级立即生效并回到战斗。
- **AC-INPUT-05** 胜利和失败结算页都提供重开入口；点击重开后回到新一局初始状态。
- **AC-INPUT-06** Esc 或 P 能暂停和恢复游戏；暂停时战斗计时、刷怪、敌人、弹体和经验移动停止，但暂停 UI 或恢复操作仍可用。
- **AC-INPUT-07** 升级弹窗期间战斗暂停，升级 UI 仍可点击；选定升级后战斗恢复。

## 四、核心循环

- **AC-LOOP-01** 一局从开始到结束形成完整闭环：进入地图、自动放豌豆、刷怪、敌人掉经验、升级三选一、波次推进、胜利或失败、结算、重开。
- **AC-LOOP-02** 戴夫初始血量为 100；戴夫血量降到 0 时进入失败结算。
- **AC-LOOP-03** 撑过第 5 波，或在规定时间内存活到最后，进入胜利结算。
- **AC-LOOP-04** 一局正常时长落在 3 到 5 分钟内；调试加速模式不受此限制，但不能改变正常模式口径。
- **AC-LOOP-05** 结算页展示：胜利或失败、存活时间、击败敌人数、放出豌豆总数、最常用豌豆或最高伤害豌豆、升级次数。
- **AC-LOOP-06** 重开后，戴夫血量、波次、敌人、弹体、经验、升级层数、已解锁武器和计时都回到一局初始状态。

## 五、战斗机制

- **AC-COMBAT-01** 戴夫与敌人发生身体接触时，会按照 `spec/游戏机制.md` 的受击规则扣血，并触发受击反馈；受击后进入短暂无敌，同一段无敌时间内重复接触敌人不能连续扣血。不能出现正常画面中僵尸已经接触戴夫但血量不变的情况。
- **AC-COMBAT-02** 橘豌豆开局即拥有；橘豌豆发射后朝当时距离最近的敌人直线扑击，不是随机方向。
- **AC-COMBAT-03** 熔岩豌豆在第 1 波结束后自动解锁；熔岩豌豆飞向敌人密集处，接近后触发一次范围爆炸并消失。
- **AC-COMBAT-04** 西瓜豌豆在第 3 波结束后自动解锁；西瓜豌豆沿短弧线或回旋弹道飞行，飞行途中可命中多个敌人，达到命中次数、飞出范围或飞行时间结束后消失。
- **AC-COMBAT-05** 每只豌豆弹都有明确的伤害、飞行速度、飞行时间、命中逻辑和同屏上限；达到上限后不能无限新增。
- **AC-COMBAT-06** 三种豌豆在机制上确实不同：橘豌豆按最近敌人直线扑击，熔岩豌豆按敌群密集处触发范围爆炸，西瓜豌豆按短弧线或回旋弹道扫场。
- **AC-COMBAT-07** 四种僵尸在机制上确实不同：普通僵尸直线追击，小僵尸速度更快且更脆，铁桶僵尸血量更高且更慢，远程僵尸保持距离并吐毒液。
- **AC-COMBAT-08** 远程僵尸的毒液有明确伤害、飞行速度和发射间隔；毒液数量和频率不能密集到遮挡主要战斗。
- **AC-COMBAT-09** 敌人死亡后掉落经验；经验进入吸附范围后自动飞向戴夫并增加升级进度。
- **AC-COMBAT-10** 屏幕外敌人只保留必要状态；靠近戴夫一定距离后才进入完整追踪、动画和碰撞逻辑。

## 六、波次与成长

- **AC-GROWTH-01** 波次顺序固定为：第 1 波普通僵尸，第 2 波加入橄榄球小僵尸，第 3 波加入铁桶大僵尸，第 4 波加入吐毒液远程僵尸，第 5 波混合僵尸群。
- **AC-GROWTH-02** 第 1 波结束后，已解锁武器从「橘豌豆」变为「橘豌豆 + 熔岩豌豆」。
- **AC-GROWTH-03** 第 3 波结束后，已解锁武器变为「橘豌豆 + 熔岩豌豆 + 西瓜豌豆」。
- **AC-GROWTH-04** 武器获得不进入随机升级池，只按波次固定解锁。
- **AC-GROWTH-05** 升级使用三选一；每次出现 3 个升级项，均来自 U01 到 U04 的基础属性升级表。
- **AC-GROWTH-06** U01「豌豆豌豆连发」最多 4 层，作用于所有豌豆；每层效果为发射冷却 -15%，具体叠加方式按事实源或已拍板配置的唯一口径执行。
- **AC-GROWTH-07** U02「增加伤害」最多 4 层，作用于所有豌豆；每层效果为伤害 +20%，具体叠加方式按事实源或已拍板配置的唯一口径执行。
- **AC-GROWTH-08** U03「豌豆加速」最多 3 层，作用于所有豌豆；每层效果为飞行速度 +15%，具体叠加方式按事实源或已拍板配置的唯一口径执行。
- **AC-GROWTH-09** U04「跑快一点」最多 3 层，作用于戴夫；每层效果为移动速度 +12%，具体叠加方式按事实源或已拍板配置的唯一口径执行。
- **AC-GROWTH-10** 升级项达到上限后，不再出现在后续三选一里。
- **AC-GROWTH-11** 一局正常游玩通常出现 4 到 6 次升级；用于验收的固定种子应能证明这个节奏成立。
- **AC-GROWTH-12** U01、U02、U03 这类对“所有豌豆”生效的升级，必须覆盖当时已解锁的每一种豌豆，并从下一次发射起生效。
- **AC-GROWTH-13** 如果可选升级项不足 3 个，升级 UI 和选择规则必须按事实源或已拍板配置处理，不能临时塞入已达上限的升级项。

## 七、地图、镜头与场景

- **AC-MAP-01** 游戏使用一张固定户外大地图，不做地图切换、随机地图、迷宫、钥匙门或复杂探索。
- **AC-MAP-02** 地图面积明显大于屏幕，镜头只显示地图的一部分，而不是一次性显示整张地图。
- **AC-MAP-03** 设计分辨率为 1920x1080；主地图 `full_outdoor_map_painted_4096x2305.png` 一屏约看到整图的四分之一，Camera2D zoom 保持在 0.8 到 1.2 之间。
- **AC-MAP-04** HUD 使用 CanvasLayer 或等价方式固定在屏幕上，镜头移动时 HUD 比例和位置不随地图漂移。
- **AC-MAP-05** 环境装饰按 v0.1 画面基准叠加，只增加画面层次，不承担复杂探索或关键玩法逻辑；玩家出生点和刷怪区附近保持可读、不过度拥挤。
- **AC-MAP-06** 地图边界通过围栏、树墙、石墙、水面或其他视觉方式表达清楚，玩家不会因为边界不清而误判可走区域。

## 八、UI 与画面

- **AC-UI-01** HUD 布局符合 `spec/视觉规格.md` 和 v0.1 战斗 HUD 画面基准：左上头像、血条、经验条、已解锁豌豆图标、顶部波次提示、右上击杀数和计时的相对位置、比例、层级和对齐关系不能明显偏离。
- **AC-UI-02** 升级三选一面板居中弹出；弹出时战场压暗，三个升级项以三张并排的竖向大卡片呈现。每张卡片都能清楚看到升级名称、效果、当前层数或上限信息，并且点击反馈清楚。
- **AC-UI-03** 胜利和失败结算面板居中弹出，按钮和结算统计不互相遮挡。
- **AC-UI-04** 血条、经验条、图标、按钮、标题、统计文字之间不重叠、不裁切、不被战斗特效遮住；关键遮挡数为 0。血条和经验条的槽体、内容区和填充区对齐，按 `spec/视觉规格.md` 中的 HUD 像素容差规则验收；填充不能偏出边框、悬空、错位或出现孤立色块。
- **AC-UI-05** UI 文案使用中文；画面上不出现“已完成某需求”之类给验收者看的说明文字。
- **AC-UI-06** 角色、豌豆弹、毒液和四种僵尸的方向动画符合 `spec/视觉规格.md`：运行时必须按当前移动或飞行方向切换对应 8 向动画，不能只加载 8 向图集但固定播放单一方向。
- **AC-UI-07** UI 控件、命中、爆炸、经验和死亡等 VFX 使用按运行尺寸准备的定制资产或粒子效果；资产位置必须符合 AC-RUN-03，不能直接切原始参考大图凑成最终效果，也不能只用纯色框或默认控件代替。定制资产不能作为改变 Spec 绑定结构的理由；如果 Spec 已指定视觉结构，最终实现必须先满足结构一致，再判断风格完成度。
- **AC-UI-08** 画面整体保持手绘描边、暗色高对比的漫画街机风；不做像素化处理，导入过滤按 `assets/sprites/README.md` 的当前规则执行。不把参考图当成最终 UI 直接贴上去，但必须保留 Spec 明确标为视觉目标的结构、比例和视觉重心。
- **AC-UI-09** 升级弹窗必须以 `spec/v0.1-画面基准-升级弹窗示意.png` 作为视觉目标。正式验收时必须保存真实运行截图，并与示意图并排核对：弹窗位置、战场压暗、三卡并排结构、卡片竖向比例、卡片间距、外框和内框层级、下半部说明区、底部圆形徽章或图标位都不得明显偏离。改成长条按钮列表、普通菜单列表、默认系统面板，或只保留“居中三选一”但结构不像示意图的方案，视为不通过。
- **AC-UI-10** 升级卡、HUD 主框、结算面板、暂停面板和提示横幅这类核心 UI，必须使用 `assets/sprites/ui/runtime/` 中的运行时 UI 资产，或使用由这些资产建出的 `.tres`；不能主要依赖 `draw_rect`、`draw_line`、`draw_circle`、默认控件或单色 `StyleBoxFlat` 模拟。升级卡必须能追溯到 `assets/sprites/ui/reference_crops/` 中的对应参考 crop，并保留参考 crop、运行时资产、真实运行截图 crop 和并排对照证据。
- **AC-UI-11** 正常游玩截图和正式视觉验收截图中不得出现调试辅助痕迹：碰撞半径圈、攻击半径圈、激活范围圈、刷怪区矩形、地图边界矩形、敌人类型文字标签、AI 状态标签、对象池标记、坐标标记或开发者辅助线。需要这些信息时必须通过显式调试入口单独截图，并在报告里标明调试辅助层已开启。

## 九、反馈与音效

- **AC-FEEDBACK-01** 敌人被打到时有闪白、闪烁、粒子或其他可见受击反馈。
- **AC-FEEDBACK-02** 豌豆命中有反馈；熔岩豌豆爆炸有范围特效；西瓜豌豆扫场能看出命中过程。
- **AC-FEEDBACK-03** 戴夫受击时有可见反馈，并能从 HUD 血量变化看出扣血。
- **AC-FEEDBACK-04** 战斗中有轻微震屏、视觉抖动或短暂停顿等打击反馈，但不能影响玩家读 UI 和走位。
- **AC-FEEDBACK-05** 下列事件都有对应音效真实触发：发橘豌豆、发熔岩豌豆、发西瓜豌豆、毒液、命中、熔岩豌豆爆炸、敌人死亡、戴夫受击、吃经验、升级、选择升级、波次开始、解锁新豌豆、胜利、失败。
- **AC-FEEDBACK-06** 配置中的音效事件都能加载到真实音频文件；不能出现事件指向缺失文件、空音频或静音占位的情况。

## 十、性能与稳定性

- **AC-PERF-01** 豌豆弹、毒液和敌人都有同屏或活跃数量上限；达到上限后节点数量不能无限增长。
- **AC-PERF-02** 豌豆弹、敌人和常见掉落物使用对象池或等价复用方式，避免大量反复创建和销毁造成卡顿。
- **AC-PERF-03** 第 5 波混合僵尸群压力场景下，游戏不能卡死、长时间冻结或出现连续致命报错。
- **AC-PERF-04** 一局从开始连续跑到胜利或失败，过程中不能出现内存、节点数量或日志错误持续增长到不可控的情况。
- **AC-PERF-05** 调试加速、截图、帧序列和状态快照只能作为辅助验证工具，不能改变正常模式下的玩法结果。

## 十一、整体成型

- **AC-SHAPE-01** 不看文档的验收者看 10 秒正常战斗画面，能说出“戴夫在自动放豌豆打僵尸”或意思等价的描述。
- **AC-SHAPE-02** 不看文档的验收者看正常战斗片段后，能用自己的话说出三种豌豆的大致差异；这里验体感可读性，不替代 AC-COMBAT-06 的机制检查。
- **AC-SHAPE-03** 不看文档的验收者看正常战斗片段后，能用自己的话说出四种僵尸的大致压力差异；这里验体感可读性，不替代 AC-COMBAT-07 的机制检查。
- **AC-SHAPE-04** 选择不同升级后，战斗效果有可感知变化：豌豆更多、豌豆更痛、豌豆更快，或戴夫更灵活。
- **AC-SHAPE-05** 结算页能证明这是一局完整游戏，而不是只展示一个胜利或失败文本。
- **AC-SHAPE-06** 不看文档的验收者看正常战斗画面时，应认为主要可见元素属于游戏世界、角色、UI 或战斗特效，而不是开发调试标记。

## 十二、需要拍板的数值口径

下面这些不是测试用例，也不是本文档偷偷替 spec 定数值。它们是 `test-author` 写详细测试前必须有唯一口径的项目。口径可以来自 `spec/游戏机制.md` 的后续补充，也可以来自用户确认后的集中配置；但不能由写实现或写测试的 Agent 临时猜一个。

- 戴夫受击后的无敌时长。
- 同屏豌豆弹、毒液和敌人的上限。
- 三种豌豆的基础伤害、飞行速度、飞行时间、发射冷却和各自上限。
- U01 到 U04 的升级叠加方式：每层按加法叠加还是乘法叠加，以及 UI、战斗计算和状态快照如何统一展示。
- 当可选升级项不足 3 个时，三选一界面如何处理。
- 熔岩豌豆爆炸半径和爆炸伤害。
- 西瓜豌豆可命中次数、飞行范围和飞行时间。
- 四种僵尸的血量、速度、接触伤害、经验掉落和活跃范围。
- 远程僵尸毒液的伤害、速度、发射间隔和最大数量。
- 经验吸附范围和升级所需经验曲线。
- 五波的正式时间节奏、刷怪间隔和敌人组成权重。

这些数值一旦拍板，应集中写入事实源或配置，并由测试用例按同一口径验证。
