# v0.1 模块边界说明

本文档记录当前 v0.1 代码职责分工，用来复核 `AC-RUN-04`。它不定义新的玩法、数值或验收标准；玩法数值仍以 `spec/游戏机制.md` 为准，视觉要求仍以 `spec/视觉规格.md` 为准。

## 当前脚本职责

| 文件 | 当前职责 | 不负责 |
| --- | --- | --- |
| `scripts/GameConfig.gd` | 集中保存地图、玩家、豌豆、敌人、经验、升级、波次、音效路径等事实数值。 | 不执行运行时逻辑，不直接改节点状态。 |
| `scripts/DirectionUtil.gd` | 按移动方向选择 8 向动画。 | 不决定角色或弹体移动。 |
| `scripts/Player.gd` | 处理戴夫移动、输入读取、边界夹取、受击无敌和相机跟随。 | 不处理刷怪、攻击、经验、升级或结算。 |
| `scripts/Enemy.gd` | 处理单个敌人的移动、远程僵尸吐毒液请求、受击和死亡判定。 | 不生成毒液节点，不决定全局刷怪节奏。 |
| `scripts/CatProjectile.gd` | 处理单个豌豆弹的飞行、寿命、方向动画和命中记录。 | 不选择目标，不结算伤害。 |
| `scripts/MilkDrop.gd` | 处理单个毒液的飞行、寿命和所属远程僵尸计数。 | 不处理玩家扣血。 |
| `scripts/XpOrb.gd` | 处理单个经验球的吸附、飞向戴夫和收集判定。 | 不增加全局经验值，不触发升级。 |
| `scripts/GameUI.gd` | 构建和刷新 HUD、升级弹窗、暂停面板、胜负结算面板。 | 不决定玩法状态和数值变化。 |
| `scripts/SfxBus.gd` | 加载、校验、播放和统计音效事件。 | 不决定什么时候触发音效。 |
| `scripts/ValidationTools.gd` | 解析验证参数、写 JSON 报告、保存截图。 | 不承载核心游戏逻辑。 |
| `scripts/Main.gd` | 编排一局游戏：创建节点、对象池、刷怪、武器发射、碰撞结算、经验升级、胜负、报告和验证入口。 | 不保存事实数值，不绘制 UI 结构，不实现单个实体的内部运动。 |

## `Main.gd` 的边界

`Main.gd` 目前仍是 v0.1 的主编排脚本，承担较多流程串联职责。它的合理边界是：

- 读取 `GameConfig.gd` 的事实数值。
- 调用实体脚本的公开方法，例如 `Player.step_player()`、`Enemy.step_enemy()`、`CatProjectile.step_projectile()`、`XpOrb.step_xp()`。
- 维护对象池和全局列表，避免运行中频繁创建和销毁核心战斗节点。
- 处理跨对象关系，例如豌豆弹命中敌人、毒液命中戴夫、敌人死亡掉经验。
- 触发 UI 和音效，不在自身内部绘制正式 UI 资产。
- 提供默认关闭的验证入口，生成报告和截图证据。

后续如果继续扩展 v0.2，优先把以下逻辑从 `Main.gd` 拆出去：

- 刷怪和波次推进可以拆成 `WaveDirector.gd`。
- 武器发射和目标选择可以拆成 `WeaponDirector.gd`。
- 碰撞和伤害结算可以拆成 `CombatResolver.gd`。
- 验证入口和报告采样可以拆成 `ValidationProbeRunner.gd`。

## 当前复核结论

v0.1 已经把单体实体、UI、音效、数值、方向动画和验证工具拆到独立脚本；`Main.gd` 仍保留主编排职责。当前范围内这可以接受，但后续版本不应继续把新系统都塞进 `Main.gd`。
